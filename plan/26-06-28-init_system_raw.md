## 配置

要求现代化且安全并进行分类。

## 历史

所有操作都必须存储，管理后台可以选择清除某段时间，某个仓库的操作历史。

## 用户登录

支持账号密码模式，且支持OAuth2，同时支持仅OAuth模式。

可参考docs\external\oauth_integration.md，但是这个文档是仅限于我们汉化组的……我希望你能制作一个类似于插件系统的系统，然后将接入这个ZOOT的逻辑额外作为一个插件。

ZOOT会给你用户名，头像和翻译类别（例如英翻，韩翻，日翻）

同时，支持在用户页面获取，管理自己的描述，API-Key，并设置自己的翻译语言。

用户页面显示自己参与的项目，关联的账号（目前可以只支持Github），UID，加入时间，以及CP（贡献分数）。

## 翻译语言

一个项目支持设置多个源语言和一个目标语言。例如可以是en jp kr -> cn，也可以是en -> cn。
当然，包括其他的主流语言也应该予以支持。

## CP

所有翻译，编辑，校对操作，都会获取CP。
翻译与编辑权重都暂定为1
校对权重为0.3
根据编辑/翻译的与原本的字数差别，获取的CP将根据字数正相关。

## API

用户可以获取自己权限下的API Doc，使用自己的API-Key调用。

词条有原文，上下文，翻译内容，键值。

词条状态分为：
未翻译 已翻译 有疑问 已检查 已审核 已锁定 已隐藏

文件格式为

上传至少需要key，original，context。
如果key相同，那么应当覆盖原本的文本，同时设置为未翻译，在词条历史显示更改和差异。

单个项目词条可能高达20w甚至更多，所以必须保证性能。

## 权限管理

权限分为平台和具体项目。
平台上，有总管理员，管理员，维护者。

具体权限内部由权限节点管理。

总管理员可以添加管理员。
管理员可以创建，删除，管理所有项目。
维护者可以创建项目。

具体项目分为
拥有者，管理，校对，翻译。
拥有者可以随意支配自己的项目。
管理与拥有者相同，但是不能删除项目。
校对可以将文本设置为校对状态，同时也可以修改已校对的文本。
